# 투자심사 모델 생성

종목명을 받으면 인터랙티브 추정 모델을 만든다. 보고서를 문서로 쓰지 않는다 —
심사 판단이 모델의 뷰로 들어가므로 보고서와 모델의 숫자가 어긋날 수 없다.

**시작 전에 읽는다**: `framework/modeling_framework.md`, `framework/html_template_spec.md`,
`framework/ic_memo_framework.md`

**전체 절차** (종목명 하나가 입력이고, 아래를 전부 거친다):

```
1 공시 확정 (DART)   → historicals.json · dart_extract.json
2 설계               → 매출 분해 방식·바인딩·밸류에이션 방법 결정
3 data.js            → MODEL + MARKET + UNITS
4 빌드·게이트        → build_model → build_excel → validate (G1~G11 전부)
5 피어               → 국내(peer_fetch) + 해외(--foreign) + 성숙 대조군
6 컨센서스 상세      → 목표주가·투자의견·기관수·직접 EBITDA (아래 §5b)
7 분기 추적          → build_quarterly (분기 공시가 있으면)
8 심사 레이어        → MEMO(개조식) + SCENARIOS + CONSENSUS
9 브라우저 검증      → 전 뷰 + 전 노드 순회 (아래 §7)
10 산출·전달         → model.html + 심사 리포트 PDF → 커밋 → main 머지·푸시
```

기존 종목과의 비교 관점을 유지한다 — 네 종목의 괴리(삼성전기 −27% · KT&G −31% ·
티엘비 +21% · LGD +49%)와 방법이 다른 이유가 `CLAUDE.md` 진행 상황에 있다.

---

## 절대 규칙

1. **검색 스니펫으로 라인아이템을 확정하지 않는다.** 이 레포에서 검색이 틀린
   사례가 세 번 있었다 — 삼성전기 FY2021 매출이 71,997억 vs 96,750억(실제),
   FY2022 영업이익이 실제의 68%, 시가총액과 주가가 서로 안 맞음.
   확정값은 `tools/dart_fetch.py`로 공시 원문에서 가져온다.
2. **`[검증대상]`이 남아 있으면 다음 단계로 가지 않는다.**
3. **게이트 실패를 남겨두지 않는다.** G1·G2의 허용 오차는 0이다.
4. **`model.html`을 직접 고치지 않는다.** 빌드 산출물이다. 엔진 수정은
   `tools/make_template.py`에 패치로 넣고 템플릿을 다시 만든다.
5. **없는 데이터를 지어내지 않는다.** 쪼갤 근거가 없으면 거기서 멈춘다.

## 절차

### 1. 공시 확정

```bash
python3 tools/dart_fetch.py search <종목명>          # 사업보고서 목록
python3 tools/dart_fetch.py toc <접수번호>           # 목차
python3 tools/dart_fetch.py doc <접수번호> <목차번호> # 본문
```

최근 사업보고서 2~3건이면 5개년이 채워진다. 각 보고서는 3개년을 보여준다.

가져올 것:
- **연결 포괄손익계산서** — 매출액·매출원가·판관비·영업이익
- **영업부문 주석** — 부문별 매출·영업이익·감가상각비 ← 모델의 뼈대
- **연결 재무상태표** — 현금·차입금 (순차입금)
- **연결 현금흐름표** — 유형자산 취득 (CAPEX)
- **주식의 총수** — 발행주식수
- **연결 포괄손익계산서 + 배당에 관한 사항** — 지배주주 순이익·세전이익·
  법인세·DPS를 확정한다 ← 주주 몫 참고 체인(net_income·eps·dps)의 실적.
  historicals에 `net_income`·`dps` 행으로 넣어 G1이 대사한다. 스키마는
  `framework/html_template_spec.md` §2.4b "주주 몫 참고 체인"
- **비용의 성격별 분류 주석** — `dart_fetch.py costnature <접수번호>`로 추출해
  `cost_nature.json`으로 정규화한다 ← 사업 구조 뷰의 비용 블록.
  당기/전기 연쇄가 보고서 사이에서 정확히 일치하는지, Σ항목 = 합계 =
  매출 − 영업이익이 성립하는지 확인하고 어긋나는 해는 `check.gap`으로
  기록한다 (범위가 다른 공시 — LGD 2021~2022 참조). 스키마는
  `framework/html_template_spec.md` §2.4b, 선례는 다섯 종목의
  `companies/*/cost_nature.json`

확인할 것:
- 부문합 = 연결 매출액인가 (오차 0)
- 소급 재작성이 있었나 (중단영업·회계기준 변경). 있으면 어느 기준을 쓸지
  정하고 `historicals.json`의 `_기준`에 기록한다
- IR 보도자료의 부문 수치는 대개 **분기**다. 연간과 섞지 않는다

원본은 `companies/<종목>/dart_extract.json`에 출처 접수번호와 함께 남긴다.

### 2. 설계 — 숫자보다 구조를 먼저

`01_revenue_methodology.md` / `02_cost_methodology.md` / `03_valuation.md`

각 부문이 **수요 바인딩**인지 **공급 바인딩**인지 먼저 정한다. 이걸 정하지
않으면 생산능력이 남는데 capacity로 물량을 추정하는 실수가 난다.

**공시가 물량을 주지 않으면 실적 구간을 Q×P로 쪼개지 않는다.** 미지수 둘에
식 하나가 되어 어떻게 나누든 근거가 없다. 대신 추정 구간의 성장률을
물량과 단가로 나눈다 — 분석적 가치는 남고 지어낸 숫자는 없다.

### 3. data.js 작성

`templates/model_template.html`의 데이터 블록 스키마를 따른다.
선언 순서: `META` → `YRS`/`HIST_N` → `MARKET`(선택) → `UNITS` → `MODEL` →
`MEMO`(선택) → `PEERS`(선택) → `SCENARIOS`(선택).

핵심 관용구:

```js
// 실적은 확정값 그대로, 추정만 굴린다
seg: { formula:'IF(seg_actual > 0, seg_actual, PREV(seg) * (1 + vol_g) * (1 + price_g))' }

// 누적·롤포워드는 PREV 자기참조
ppe: { formula:'PREV(ppe) + capex - depreciation' }

// 상한 체크
qty: { formula:'MIN(demand_a + demand_b, capacity)' }
```

규약:
- 입력 노드 `desc`는 `[객관]`/`[주관]`/`[외생]`/`[계산]`으로 시작 (G10)
- 색은 `design-guide/tokens.js`에서만. 매출=primary 램프, 비용=neutral 램프
- `TREE`·`INPUT_KEYS`·`DEFAULTS_S`·`GRAPH`·`SIM_SECS`는 쓰지 않는다 (자동 파생)
- 음수가 정상인 계정(순차입금 등)은 `allowNegative:1`
- `MARKET`은 시장 관측치다. 가정이 아니므로 `MODEL`에 넣지 않는다

`historicals.json`에 공시 확정값을 적는다. G1이 매 빌드마다 대사한다.

### 4. 빌드와 검증

```bash
python3 tools/build_model.py companies/<종목>/data.js       # → model.html
python3 tools/build_excel.py companies/<종목>/model.html    # → model.xlsx
python3 tools/validate_model.py companies/<종목>/model.html
```

게이트 G1~G12가 전부 통과해야 한다. 하나라도 실패하면 고치고 다시 돌린다.
G12는 `cost_nature.json`(빌드가 `COSTNATURE`로 주입)을 대사한다 — MEMO를 쓰는
모델에 COSTNATURE가 없으면 실패한다 (PEERS와 같은 규약).

부문이 있는 종목은 `META.bizMap`으로 매출↔이익(또는 비용) 노드를 매핑해야
사업 구조 뷰의 이익 구조 블록이 뜬다. 부문마다 `note` 한 줄(무엇을 파는가)을
함께 적는다.

심사 레이어에 함께 넣을 것 (전부 G11이 검사):
- `MEMO.probs` + `probsNote` — 시나리오 확률([주관], 합=1)과 근거 한 줄
- `MEMO.events` — 다음 분기·사업보고서 법정 기한과 촉매 시점 (D-day 카드)
- `MARKET.history` — 최초 스냅숏 한 건. **이후 MARKET 갱신·가정 개정 때마다
  직전 (주가, 적정가) 쌍을 여기 밀어 넣는다** — 모델이 주가를 뒤쫓는지의 기록

빌드 후 워치리스트 갱신: `python3 tools/build_index.py` (루트 index.html).

### 5. 피어 그룹

목표배수(또는 WACC)는 밸류에이션 결과를 가장 크게 좌우하는 가정이다.
근거를 기억이 아니라 데이터로 둔다.

```bash
python3 tools/peer_fetch.py --json <자기코드> <피어1> <피어2> ...
```

같은 출처·같은 기준일이어야 비교가 성립한다. 종목마다 다른 사이트에서 긁으면
EBITDA 정의가 달라 표가 무의미해진다.

피어를 고를 때는 **성숙 대조군을 반드시 넣는다.** 테마주만 모으면 전부
비싸 보여서 "업종 평균이 원래 높다"는 잘못된 결론이 나온다. 재평가가 테마에
국한된 것인지 업종 전체인지는 성숙 대조군이 있어야 갈린다.

`PEERS` 블록으로 data.js에 넣으면 밸류에이션 뷰에 표가 뜬다.

**컨센서스 역산을 함께 본다.** 피어 페이지의 컨센서스 배수로
`(시총 + 순차입금) / 컨센서스 배수`를 계산하면 시장이 전제하는 이익이 나온다.
그 값과 본 모델 추정의 차이가 "시장과 나 중 누가 다른 것을 보고 있는가"를
정량화한다 — 목표가를 다투는 것보다 생산적인 질문이다.

### 5b. 컨센서스 상세 — 다른 애널리스트들과의 대조

WISEreport 스냅샷 페이지에 증권사 컨센서스의 집계본이 있다. 리포트 원문
(한경컨센서스 등)은 이그레스가 막혀 있으므로 이것이 1차 출처다.

```bash
curl -sSL --cacert /root/.ccr/ca-bundle.crt -H "User-Agent: Mozilla/5.0" \
  "https://comp.wisereport.co.kr/company/c1010001.aspx?cmp_cd=<종목코드>"
```

페이지에서 뽑는 것:
- **투자의견 컨센서스** 블록 — 투자의견 · **목표주가** · EPS · 추정기관수
- **펀더멘털 표** — 2026E·Fwd12M의 EBITDA·EPS·DPS **직접값** (역산하지 않는다)
- **기업실적코멘트** — 애널리스트들이 지목하는 드라이버. 모델의 정성 레이어가
  놓친 사실이 여기서 나온다 (티엘비의 BVH 공법·베트남 공장이 그렇게 들어왔다)

`CONSENSUS` 블록으로 넣는다:

```js
const CONSENSUS={
  asOf:'YYYY-MM-DD',
  source:'WISEreport 컨센서스 (최근 3개월 증권사 추정 평균) · 추정기관 N곳',
  targetPrice:2350500,   // 없으면 생략 — "최근 3개월 제시 없음"도 정보다(커버리지 공백)
  opinion:4.00, nAnalysts:20,
  items:[{year:2026, node:'ebitda', value:30300}],
};
```

화면이 목표주가 행을 자동으로 만든다 — 애널리스트 평균 목표가와 본 모델 주당
가치가 같은 행에 놓인다. **"시장(주가)과 다르다"와 "애널리스트들과 다르다"는
별개의 정보다.** 방향이 다르면(삼성전기: 컨센 +70% vs 모델 −27%) 그 사실을
심사 쟁점(debate)에 양쪽 논거로 넣는다 — 20곳이 일제히 반대 방향이면 모델이
못 보는 정보가 있을 가능성도 논거다.

주의:
- WISE의 EBITDA는 무형자산상각 포함이라 본 모델 정의(영업이익+감가상각)보다
  넓다. 대조표에 주석으로 남긴다.
- 목표주가는 대체로 12개월 시계, 본 모델은 최종 추정 연도 시계다. 명시한다.
- 해외 피어는 `python3 tools/peer_fetch.py --foreign` (stockanalysis.com).
  시가총액은 현지 통화 그대로(`cap:'5.91조엔'`), 비교는 배수로만.

### 6. 심사 레이어

`MARKET`을 선언하면 사이드바에 Investment case 그룹 6종이 나타난다 —
투자 개요 · 밸류에이션 · 시나리오 · 투자 아이디어 · 심사 결론 · 심사 리포트.
`MEMO`에 판단 텍스트를, `PEERS`에 피어 배수를, `SCENARIOS`에 Bull/Bear 프리셋을
넣는다. Base는 초안값 그 자체이므로 케이스로 두지 않는다.

시나리오는 **`[주관]` 노드만 흔든다.** `[객관]`을 흔들면 시나리오가 아니라
다른 모델이다.

**문체 — 개조식.** 종결은 "~함/~임/명사형". 결론은 명사구로 앞세운다
("투자 판단은 패키지솔루션에 달려 있다" → "투자판단의 Key는 패키지솔루션").
`points`·`thesis`·`catalysts`·`kpis`·`risks`는 `'한 줄'` 또는
`{t:'주제', d:['근거','근거']}` 두 형태만 — 화면이 ▪/– 두 층으로 조판한다.
문단이 필요하면 `lead` 한 줄만. 게이트 G11이 형태를 검사한다.

**강조는 `**굵게**`, 한 항목에 하나만.** 둘 이상 굵게 하면 아무것도 강조되지 않는다.

**차트.** 표는 값을, 차트는 추세를 준다. `icSvgBars`(추세) · `icSvgHBars`(순위) ·
`icSvgStack`(구성비) 셋을 `icChartCard`로 감싸 쓴다. 인라인 SVG이므로 외부 요청 0건
규약을 깨지 않는다.

**숫자 인용.** 산문의 모델 숫자는 `{{node@연도}}`로 적는다. 손으로 적으면 가정을
바꿨을 때 본문만 낡는다.

**분기 추적.** `python3 tools/build_quarterly.py companies/<종목>/quarterly.json` 으로
DART 영업부문 주석에서 분기 확정값을 만든다. `build_model.py`가 자동 주입하고
분기 모니터링 뷰가 켜진다. `ideas[].track`에 `{label, seg, metric, good}`을 적으면
확인지표를 화면이 계산한다.

**정성 레이어.** `MEMO.ideas`에 투자 아이디어를, `MEMO.debate`에 심사 쟁점을
적는다. 아이디어마다 `falsify`(반증 조건)가 **필수**다 — 무엇을 보면 틀렸다고
인정할지 미리 적어두지 않으면 지표가 훼손돼도 사후에 합리화된다. 쟁점은
`yes`와 `no`를 같은 무게로 적는다. 스키마는 `framework/ic_memo_framework.md` §4.1.

**심사 리포트.** 위 전부를 10개 섹션 한 장으로 조판한 뷰가 자동으로 생긴다.
`@media print`가 붙어 브라우저 인쇄로 PDF가 나온다. 리포트 본문의 숫자는 전부
`MODEL`에서 그 자리에서 다시 읽으므로 **본문에 숫자를 손으로 적지 않는다** —
이것을 어기는 순간 리포트와 모델이 어긋난다.

---

### 7. 브라우저 검증 — 게이트가 못 보는 것

게이트는 값을 검사하고, 화면은 브라우저에서만 깨진다. Playwright(chromium은
`/opt/pw-browsers/chromium`)로 전 뷰를 순회한다:

- 사이드바의 **모든 뷰**(`.nav-item`의 data-view) + **모든 노드 상세**를 열어
  `undefined`·`NaN`·`Infinity`·`{{`(미해석 인용)·`-100.0%`를 스캔
- 차트 SVG의 선 좌표가 viewBox 경계 안인지 (음수 계열이 밖으로 나간 전례)
- 시뮬레이터 왕복 후 루트 값 복원 확인
- 모바일 390×844 — ☰·서랍·가로 넘침
- 외부 요청 0건 (`page.on('request')`)
- 인쇄 미디어에서 셸이 사라지는지, PDF 페이지수

**새 종목마다 엔진 결함이 나온다는 전제로 본다.** 지금까지 종목마다 3건씩
나왔다(KT&G: UNITS 선택 필드·ebitda 전제·— 표기 / 티엘비: 노드명 전제·
곱셈 분해 스택·선 축 라벨 / LGD: 음수 선 좌표·가짜 분해·YoY 부호 반전).
결함은 `tools/make_template.py`에 패치로 넣고 템플릿을 재생성한다 —
그래야 네 종목이 전부 같은 수정을 받고 G9(Tesla 회귀)가 지켜준다.

## 밸류에이션 방법 선택

| 상황 | 방법 | 전례 |
|---|---|---|
| 증설 사이클 중이라 FCF 진폭이 큼 | EV/EBITDA 배수법 | 삼성전기 (18배) |
| 현금흐름이 안정적이고 CAPEX 예측 가능 | DCF | KT&G (WACC 8%) |
| 공시가 단가·생산능력을 줌 | Q×P + 공급 바인딩, EV/EBITDA | 티엘비 (12배) |
| 적자 사이클·턴어라운드 | EV/EBITDA를 사이클 중립 배수로 | LGD (3.5배) |
| 어느 쪽이든 | **역산을 함께 낸다** — 현재 가격이 전제하는 실적 | 전 종목 |

적자 기업 주의: `allowNegative:1`을 계산 노드(영업이익·루트)에도 달아야
검증·이슈에 뜨지 않는다. 사이클 상단 배수를 사이클 상단 실적에 곱하지 않는다
— 이중 계상이다.

역산이 목표가 제시보다 심사에 유용할 때가 많다. 특히 주가가 급등해
실적 기반 모델과 가격이 크게 벌어진 종목에서 그렇다.
"적정가가 얼마인가"보다 "지금 가격이 무엇을 전제하는가"가 답할 수 있는 질문이다.

## 자주 나오는 실수

| 실수 | 결과 |
|---|---|
| IR 보도자료의 분기 수치를 연간으로 씀 | 부문합이 총매출과 안 맞음 (G1이 잡는다) |
| 소급 재작성 기준을 섞음 | 연도 간 비교가 깨짐 |
| 감가상각비를 매출에 연동 | 하강 국면의 이익 훼손을 과소평가 |
| Base에 마진 회복을 embed | Base가 사실상 Bull이 됨 |
| 피어를 테마주로만 채움 | 전부 비싸 보여 "업종 평균이 높다"는 잘못된 결론 |
| 컨센서스를 확인하지 않음 | 모델과 시장의 차이가 어디서 오는지 모른 채 목표가만 다툼 |
| 컨센서스를 배수에서 역산 | 스냅샷 페이지 펀더멘털 표가 EBITDA·EPS·DPS 직접값을 준다. 목표주가·투자의견·기관수도 같은 페이지에 있다 |
| 컨센서스 PER와 모델을 직접 비교 | 본 모델에는 EPS 레이어가 없다 (의도적 공백 — ic_memo_framework §5.5) |
| 목표배수 근거를 안 적음 | 결과를 지배하는 가정이 검증 불가 |
| 아이디어에 반증 조건을 안 적음 | 분기 리뷰가 "여전히 유효하다"의 반복이 됨 |
| 리포트 본문에 숫자를 손으로 적음 | 가정을 바꾸면 본문만 옛 숫자로 남는다 |
| 닿지 않는 출처의 값을 기억으로 채움 | 이 레포에서 이미 세 번 틀렸다. 못 구하면 비워 두고 `missing`에 적는다 |
| 본문을 서술형 문단으로 씀 | 심사장에서 안 읽힌다. ▪/– 두 층 항목으로 |
| 실적이 앞설 때마다 가정을 조금씩 상향 | 모델이 주가를 뒤쫓는다. 일괄 재보정하고 `MEMO.revision`에 기록 |
| 재보정에서 유리한 방향만 반영 | 재보정이 아니라 합리화. 불리한 것도 함께 올린다 |
| 엔진이 특정 노드 이름을 전제 | `ebitda` 없는 DCF 모델에서 화면이 빈다. 노드 유무를 확인하고 분기 처리 |
