# 데이터 요청서 — 삼성전기 (009150)

`historicals.json`을 채우는 데 필요한 항목. **공시 원문**에서 가져온다.
이 파일이 채워지면 검증 게이트 G1이 대사를 시작하고, `data.js` 작성이 가능해진다.

---

## 왜 필요한가

이 환경에서 DART·IR 사이트 접근이 차단돼 검색 스니펫만 확보 가능한데,
검색 결과가 서로 충돌했다 (FY2021 매출이 한 곳은 71,997억, 다른 곳은 96,750억).
근사치를 모델에 넣으면 전 연도 추정이 함께 틀어지므로 넣지 않았다.

---

## 필요한 항목

### 1. 연결 손익계산서 (필수)

최근 **5개 사업연도**. 사업보고서 → 재무제표 → 연결 포괄손익계산서.

| 항목 | 비고 |
|---|---|
| 매출액 | 연결 기준 |
| 매출원가 | 비용 레이어(Phase 2)에서 사용 |
| 매출총이익 | |
| 판매비와관리비 | |
| 영업이익 | |

### 2. 부문별 정보 (필수 — 이게 핵심)

사업보고서 → 주석 → **영업부문 정보**. 또는 IR 실적발표의 부문별 매출.

최근 5개 사업연도, **연간** 기준:

| 부문 | 매출액 | 영업이익 |
|---|---|---|
| 컴포넌트 | | |
| 광학통신솔루션 | | |
| 패키지솔루션 | | |
| 부문 간 내부거래 제거 | | 별도 공시되면 |
| **합계** | | 총매출과 일치해야 함 |

> **주의**: IR 보도자료의 부문별 수치는 대개 **분기** 기준이다.
> 연간과 분기를 섞으면 안 된다. 검색 결과에서 실제로 이 혼동이 있었다.

### 3. 유형자산·CAPEX (Phase 2용)

| 항목 | 비고 |
|---|---|
| 유형자산 기초/기말 장부가 | 롤포워드 검증용 |
| 유형자산 취득(CAPEX) | 증설 규모 |
| 감가상각비 | 원가의 큰 축 |

### 4. 정성 지표 (있으면 좋음)

IR 자료·컨퍼런스콜에서 회사가 밝힌 비중. 없으면 추정으로 대체한다.

- 컴포넌트 내 **전장·서버향 매출 비중** (%)
- 패키지솔루션 내 **FC-BGA 비중** (%)
- 패키지 라인 증설 계획 — 양산 시점, 투자 규모

## 전달 방법

아무 형태나 괜찮다. 편한 쪽으로.

1. **`historicals.json` 직접 작성** — 아래 스키마
2. **엑셀·CSV 첨부** — 부문 × 연도 격자면 충분
3. **사업보고서 해당 페이지 붙여넣기** — 표를 그대로

## historicals.json 스키마

```json
{
  "_source": "삼성전기 사업보고서 (2025.12) 연결 포괄손익계산서 · 영업부문 정보",
  "_unit": "억원",
  "_years": ["2021", "2022", "2023", "2024", "2025"],

  "root":            [ , , , , ],
  "component_total": [ , , , , ],
  "optics_total":    [ , , , , ],
  "package_total":   [ , , , , ]
}
```

- 키는 `data.js`의 노드 id와 같아야 한다.
- 값 배열의 길이는 실적 연도 수(`HIST_N`)와 같다.
- `_`로 시작하는 키는 검증에서 무시한다 — 출처·단위 메모용.

게이트 G1이 이 값과 모델 산출값을 대사하고, 하나라도 어긋나면 실패한다.
