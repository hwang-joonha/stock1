# 투자심사 레이어 규약

추정 모델 위에 심사 판단을 얹는 방법. Phase 3에서 구현한다.
이 문서는 **무엇을 만들지**를 먼저 못박아 두기 위한 것이다.

---

## 1. 원칙 — 보고서를 따로 쓰지 않는다

투자심사 보고서를 별도 문서로 만들면 모델과 즉시 어긋난다.
가정을 하나 바꾸면 보고서의 숫자를 손으로 고쳐야 하고, 그 순간
"어느 쪽이 맞는가"를 아무도 답할 수 없게 된다.

그래서 심사 내용을 **모델의 뷰로 넣는다.** 엔진에 이미 뷰 라우팅
(`go(view)` / `renderView()` / `VIEW_TITLES`)이 있으므로 그룹 하나를 더한다.

```
Overview         전체 캔버스 · 요약 대시보드
계정 트리         (MODEL에서 자동 생성)
Investment case  투자 개요 · Thesis · 밸류에이션 · 시나리오 · 리스크 · 심사 결론
Model control    가정·근거 · 전체 테이블 · 검증·이슈
```

심사 뷰의 모든 수치가 `MODEL`에서 나온다. 보고서와 모델이 어긋날 경로가
구조적으로 없다.

---

## 2. 밸류에이션은 문서가 아니라 노드다

WACC · terminal growth · 목표 멀티플을 `type:'input'` 노드로 넣는다.
그러면 기존 시뮬레이터 슬라이더가 그대로 붙는다.

```
영업이익 (모델 루트)
  → nopat            = op_profit * (1 - tax_rate)
  → fcf              = nopat + depreciation - capex - wc_change
  → ev_dcf           = 현재가치 합 + terminal_value
  → equity_value     = ev_dcf - net_debt
  → target_price     = equity_value / shares_outstanding
```

`net_debt`는 `PREV(net_debt) + capex - ocf` 형태의 롤포워드다.
엔진의 시차 참조로 표현된다.

**효과**: 심사위원이 "출하 성장률을 2%p 낮추면 목표가가 얼마인가"라고 물으면
그 자리에서 슬라이더를 움직여 답한다. 문서로 뽑아두면 불가능한 일이다.

---

## 3. 시나리오

엔진에 케이스 저장·전환(`_cases`)이 이미 있다.
Bull / Base / Bear는 새로 만드는 기능이 아니라 **프리셋 3개를 등록**하는 일이다.

규칙:
- `[주관]` 노드만 움직인다. `[객관]`을 흔들면 시나리오가 아니라 다른 모델이다.
- 각 시나리오가 어떤 노드를 어떻게 바꿨는지 명시한다.
- Base는 초안값 그대로. 별도 케이스로 저장하지 않는다.

---

## 4. 심사 뷰

사이드바 `Investment case` 그룹. `MARKET`이 선언된 모델에서만 뜬다.

| 뷰 | 내용 | 데이터 출처 |
|---|---|---|
| 투자 개요 | 현재 시총 · 적정 시총 · 괴리 · 현재가 함의 배수 | 모델 루트 + `MARKET` |
| 밸류에이션 | 목표배수 민감도 · 역산 · 피어 비교 | 밸류에이션 노드 + `PEERS` |
| 시나리오 | Bull/Base/Bear 비교 + 흔든 가정 일람 | `SCENARIOS` 프리셋 |
| 투자 아이디어 | 아이디어별 논거 · 촉매 · 확인지표 · 리스크 · 반증 조건 | `MEMO.ideas` |
| 심사 결론 | 투자의견 · 쟁점 · 상방/하방 · 모니터링 | `MEMO` |
| 심사 리포트 | 위 전부를 한 장으로 조판. 인쇄·PDF 전제 | 위 전부 |

판단 텍스트는 `MEMO`에 둔다. 모델 수치와 섞지 않는다 —
리포트 본문의 숫자는 전부 `MODEL`에서 그 자리에서 다시 읽으므로
가정을 바꾸면 본문도 함께 바뀐다. 본문에 숫자를 손으로 적지 않는 것이 규칙이다.

### 4.1 `MEMO` 스키마

```js
const MEMO = {
  // 서술 카드 — {sub, lead, points[]}
  company:{...}, thesis:{...}, valuation:{...},
  verdict:{...}, bull:{...}, bear:{...}, risk:{...},

  // 투자 아이디어 — 배열. 순서가 번호가 된다.
  ideas:[{
    title:      '한 줄로 읽히는 아이디어',
    horizon:    '12~24개월',      // 투자기간
    conviction: '중',             // 확신도 — 주관임을 밝힌다
    tag:        '이익 회복',       // 분류 (선택)
    thesis:     '왜 그런가. 모델 수치를 인용해 쓴다.',
    catalysts:  ['무엇이 일어나면 실현되는가'],
    kpis:       ['분기마다 무엇을 볼 것인가'],
    risks:      ['무엇이 이 아이디어를 깨는가'],
    falsify:    '무엇을 보면 틀렸다고 인정할 것인가',   // 필수
  }],

  // 심사 쟁점 — 한 질문에 양쪽을 함께
  debate:[{ q:'질문', yes:'그렇다는 논거', no:'아니라는 논거' }],
};
```

**`falsify`가 없는 아이디어는 아이디어가 아니다.** 무엇을 보면 틀렸다고
인정할지 미리 적어두지 않으면, 지표가 훼손돼도 사후에 합리화된다.
심사에서 검증할 수 없는 논거는 논거가 아니라 주장이다.

**`debate`는 한쪽만 적을 수 없다.** `yes`와 `no`를 같은 무게로 적는다.

## 5. 분석 품질 기준

- **Bull과 Bear를 항상 병기한다.** 한쪽만 있으면 심사 자료가 아니라 홍보물이다.
- **회사 홍보 문구를 비판적으로 검증한다.** "세계 최초", "독보적"은 근거가 아니다.
- **서사와 검증을 구분한다.** 지금 돈을 버는 사업과 주가 프리미엄을 만드는
  사업은 대개 다르다. 나눠서 설명한다.
- **주관 평가는 주관이라고 밝힌다.** 스코어카드·등급은 분석자 판단이다.
- **수치는 출처와 함께.** 변동하는 값은 최신 공시로 재확인한다.
- **아이디어마다 반증 조건을 적는다.** `MEMO.ideas[].falsify`. 이것이 없으면
  분기 리뷰가 "여전히 유효하다"는 말만 반복하게 된다.
- **쟁점은 양쪽을 적는다.** `MEMO.debate`. 한쪽만 적은 것은 논거가 아니라 주장이다.

---

## 6. 면책

투자심사 보고서는 내부 판단 자료다. 라이선스 보유 자문가의 투자권유가 아니며,
모든 수치는 최신 공시로 재확인해야 한다는 문구를 산출물에 포함한다.
