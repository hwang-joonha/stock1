# 투자심사 레이어 규약

추정 모델 위에 심사 판단을 얹는 방법. Phase 3에서 구현한다.
이 문서는 **무엇을 만들지**를 먼저 못박아 두기 위한 것이다.

---

## 1. 원칙 — 보고서를 따로 쓰지 않는다

투자심사 보고서를 별도 문서로 만들면 모델과 즉시 어긋난다.
가정을 하나 바꾸면 보고서의 숫자를 손으로 고쳐야 하고, 그 순간
"어느 쪽이 맞는가"를 아무도 답할 수 없게 된다.

그래서 심사 내용을 **모델의 뷰로 넣는다.** 엔진에 이미 뷰 라우팅
(`go(view)` / `renderView()` / `VIEW_TITLES`)이 있으므로 그룹 하나를 더한다.

```
Overview         전체 캔버스 · 요약 대시보드
계정 트리         (MODEL에서 자동 생성)
Investment case  투자 개요 · Thesis · 밸류에이션 · 시나리오 · 리스크 · 심사 결론
Model control    가정·근거 · 전체 테이블 · 검증·이슈
```

심사 뷰의 모든 수치가 `MODEL`에서 나온다. 보고서와 모델이 어긋날 경로가
구조적으로 없다.

---

## 2. 밸류에이션은 문서가 아니라 노드다

WACC · terminal growth · 목표 멀티플을 `type:'input'` 노드로 넣는다.
그러면 기존 시뮬레이터 슬라이더가 그대로 붙는다.

```
영업이익 (모델 루트)
  → nopat            = op_profit * (1 - tax_rate)
  → fcf              = nopat + depreciation - capex - wc_change
  → ev_dcf           = 현재가치 합 + terminal_value
  → equity_value     = ev_dcf - net_debt
  → target_price     = equity_value / shares_outstanding
```

`net_debt`는 `PREV(net_debt) + capex - ocf` 형태의 롤포워드다.
엔진의 시차 참조로 표현된다.

**효과**: 심사위원이 "출하 성장률을 2%p 낮추면 목표가가 얼마인가"라고 물으면
그 자리에서 슬라이더를 움직여 답한다. 문서로 뽑아두면 불가능한 일이다.

---

## 3. 시나리오

엔진에 케이스 저장·전환(`_cases`)이 이미 있다.
Bull / Base / Bear는 새로 만드는 기능이 아니라 **프리셋 3개를 등록**하는 일이다.

규칙:
- `[주관]` 노드만 움직인다. `[객관]`을 흔들면 시나리오가 아니라 다른 모델이다.
- 각 시나리오가 어떤 노드를 어떻게 바꿨는지 명시한다.
- Base는 초안값 그대로. 별도 케이스로 저장하지 않는다.

## 4. 심사 뷰

사이드바 `Investment case` 그룹. `MARKET`이 선언된 모델에서만 뜬다.

| 뷰 | 내용 | 데이터 출처 |
|---|---|---|
| 투자 개요 | 현재 시총 · 적정 시총 · 괴리 · 현재가 함의 배수 | 모델 루트 + `MARKET` |
| 밸류에이션 | 목표배수 민감도 · 역산 · 피어 비교 | 밸류에이션 노드 + `PEERS` |
| 시나리오 | Bull/Base/Bear 비교 + 흔든 가정 일람 | `SCENARIOS` 프리셋 |
| 투자 아이디어 | 아이디어별 논거 · 촉매 · 확인지표 · 리스크 · 반증 조건 | `MEMO.ideas` |
| 심사 결론 | 투자의견 · 쟁점 · 상방/하방 · 모니터링 | `MEMO` |
| 분기 모니터링 | 진행률 · 분기 확정 실적 · 아이디어 확인지표 | `QUARTERLY` + 모델 |
| 민감도 | 전 가정을 ±10% 흔든 토네이도 | 모델 |
| 심사 리포트 | 위 전부를 한 장으로 조판. 인쇄·PDF 전제 | 위 전부 |

판단 텍스트는 `MEMO`에 둔다. 모델 수치와 섞지 않는다 —
리포트 본문의 숫자는 전부 `MODEL`에서 그 자리에서 다시 읽으므로
가정을 바꾸면 본문도 함께 바뀐다. 본문에 숫자를 손으로 적지 않는 것이 규칙이다.

### 4.1 `MEMO` 스키마

```js
const MEMO = {
  // 서술 카드 — {sub, lead, points[]}
  company:{...}, thesis:{...}, valuation:{...},
  verdict:{...}, bull:{...}, bear:{...}, risk:{...},

  // 투자 아이디어 — 배열. 순서가 번호가 된다.
  ideas:[{
    title:      '한 줄로 읽히는 아이디어',
    horizon:    '12~24개월',      // 투자기간
    conviction: '중',             // 확신도 — 주관임을 밝힌다
    tag:        '이익 회복',       // 분류 (선택)
    update:     '최신 확정 분기가 이 아이디어에 무엇을 말하는가',  // 논거보다 먼저 읽힌다
    thesis:     [항목],            // 왜 그런가
    catalysts:  [항목],            // 무엇이 일어나면 실현되는가
    kpis:       [항목],            // 분기마다 무엇을 볼 것인가
    risks:      [항목],            // 무엇이 이 아이디어를 깨는가
    falsify:    '무엇을 보면 틀렸다고 인정할 것인가',   // 필수
    // 화면이 계산하는 확인지표. QUARTERLY에서 직접 읽는다.
    track:[{ label:'패키지 영업이익률', seg:'패키지솔루션',
             metric:'영업이익률',      // 매출·영업이익·감가상각비·영업이익률·기타비용률
             kind:'yoy',              // 생략하면 수준, 'yoy'면 전년 동기 대비
             good:'up' }],            // 좋은 방향 — 화면이 ▲를 어떤 색으로 칠할지
  }],

  // 심사 쟁점 — 한 질문에 양쪽을 함께
  debate:[{ q:'질문', yes:'그렇다는 논거', no:'아니라는 논거' }],
};
```

**`falsify`가 없는 아이디어는 아이디어가 아니다.** 무엇을 보면 틀렸다고
인정할지 미리 적어두지 않으면, 지표가 훼손돼도 사후에 합리화된다.
심사에서 검증할 수 없는 논거는 논거가 아니라 주장이다.

**`debate`는 한쪽만 적을 수 없다.** `yes`와 `no`를 같은 무게로 적는다.

### 4.2 문체 — 항목이지 문단이 아니다

심사 자료의 본문은 서술형 문단으로 쓰지 않는다. 읽는 사람이 회의 중에
훑기 때문이다. 모든 `points`·`thesis`·`catalysts`·`kpis`·`risks` 항목은
두 형태 중 하나다.

```js
points:[
  '한 줄로 끝나는 항목',                         // ▪ 한 줄
  {t:'주제 — 숫자를 포함한 요지', d:[            // ▪ 주제(굵게)
     '근거 하나',                                //   – 근거
     '근거 둘',
  ]},
]
```

- 상위 항목(`t`)은 **주제와 결론**을 한 줄에. 숫자를 여기에 넣는다.
- 하위 항목(`d`)은 **근거**를. 문장을 끝맺지 않아도 된다.
- 문단이 필요하면 `lead` 한 줄만 쓴다. 그 이상은 항목으로 쪼갠다.

게이트 G11이 이 형태를 검사한다 — `{t}` 없는 객체나 배열이 아닌 `d`는 실패다.

### 4.2b 어투 — 개조식

심사 자료는 논설문이 아니다. 종결은 **"~함 / ~임 / 명사형"**으로 쓰고,
결론은 명사구로 앞세운다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 투자 판단은 패키지솔루션 하나에 달려 있다. | 투자판단의 Key는 **패키지솔루션** |
| 감가상각이 이익을 먹고 있는 국면이다. | 증설이 이익을 소모하는 국면 |
| 반등의 근거가 지금은 없다. | 반등 근거 현재 부재 |

`lead` 한 줄만 문장으로 쓰고, 나머지는 전부 항목이다.

**강조는 `**굵게**`.** 한 항목에 하나만 — 그 항목의 결론에 해당하는 조각에.
둘 이상 굵게 하면 아무것도 강조되지 않는다. 이스케이프 뒤에 변환하므로
데이터가 태그를 주입할 수는 없다.

### 4.2c 가정을 바꿀 때 — `MEMO.revision`

실적이 가정을 앞서면 가정을 올리고 싶어진다. 그때마다 조금씩 올리면 모델이
주가를 뒤쫓게 되고 "무엇을 전제했는가"의 기록이 사라진다. 규약은 둘이다.

1. **한 번에 바꾼다.** 분기마다 조금씩이 아니라, 확정 실적이 쌓였을 때 일괄로.
2. **기록을 남긴다.** `MEMO.revision`에 기존값 → 신규값과 근거를 적는다.
   심사 결론 뷰와 리포트 §9에 결론과 같은 자리에 뜬다.

```js
revision:{
  sub:'2026-08-28 — 상반기 확정 실적 반영',
  lead:'괴리 **−55% → −27%**',
  points:[
    {t:'매출 — 상반기 실적에서 역산', d:['패키지 +15.4% → **+41.2%**']},
    {t:'바꾸지 않은 것', d:['순차입금 — 2025년 수준 고정 유지']},
  ],
},
```

**불리한 방향도 반영한다.** 유리한 것만 골라 올리면 재보정이 아니라 합리화다.
`바꾸지 않은 것` 항목을 함께 적어야 무엇을 검토했고 무엇을 남겼는지가 드러난다.

### 4.3 숫자 인용

산문 안의 모델 숫자는 손으로 적지 않는다.

```js
'본 모델 2026 EBITDA는 {{ebitda@2026}}억'      // → 20,165
'적정 시가총액 {{root@2030|money}}'             // → 46.14조원
```

`{{노드@연도}}` 또는 `{{노드@연도|money}}`. 화면이 그 자리에서 모델값을 읽으므로
가정을 바꾸면 본문도 함께 바뀐다. 해석되지 않는 인용은 G11이 잡는다.

## 4.4 차트

표는 값을 주고 차트는 추세를 준다. 심사에서는 둘 다 필요하다.
엔진이 인라인 SVG로 세 종류를 그린다 — 외부 라이브러리를 쓰지 않는 이유는
`model.html`의 외부 요청 0건 규약 때문이다.

| 함수 | 쓰임 |
|---|---|
| `icSvgBars(labels, values, {histN, line, lineLabel})` | 연도·분기 추세. 추정 구간 음영, 선으로 비율 겹치기 |
| `icSvgHBars(rows, {labelW})` | 순위 비교 (피어 배수·시나리오·민감도) |
| `icSvgStack(labels, series)` | 구성비 추이 (100% 스택) |

`icChartCard(title, sub, svg)`로 감싸면 카드 조판이 붙는다.
색은 `ICV`에서만 가져온다 — `design-guide/tokens.js`의 램프다.

## 5. 분석 품질 기준

- **Bull과 Bear를 항상 병기한다.** 한쪽만 있으면 심사 자료가 아니라 홍보물이다.
- **회사 홍보 문구를 비판적으로 검증한다.** "세계 최초", "독보적"은 근거가 아니다.
- **서사와 검증을 구분한다.** 지금 돈을 버는 사업과 주가 프리미엄을 만드는
  사업은 대개 다르다. 나눠서 설명한다.
- **주관 평가는 주관이라고 밝힌다.** 스코어카드·등급은 분석자 판단이다.
- **수치는 출처와 함께.** 변동하는 값은 최신 공시로 재확인한다.
- **아이디어마다 반증 조건을 적는다.** `MEMO.ideas[].falsify`. 이것이 없으면
  분기 리뷰가 "여전히 유효하다"는 말만 반복하게 된다.
- **쟁점은 양쪽을 적는다.** `MEMO.debate`. 한쪽만 적은 것은 논거가 아니라 주장이다.

## 5.5 증권사 리포트 대비 — 있는 것과 없는 것

컨센서스 상세(WISEreport)와 대조해 확인한 구조적 차이. (2026-08-28)

**이 파이프라인이 더 가진 것**
- 가정이 전부 조작 가능한 입력이고, 보고서 숫자가 모델에서 그 자리에서 나온다
- 반증 조건(`falsify`)과 분기 자동 추적 — 증권사 리포트에는 없는 장치
- 가정 개정 이력(`MEMO.revision`)이 결론과 같은 자리에 남는다

**증권사 리포트가 더 가진 것 (알려진 공백)**
- ~~**EPS·순이익 레이어 없음.**~~ **2026-08-29 해소.** 주주 몫 참고 체인
  (`net_income`·`eps`·`dps`)이 다섯 종목에 들어갔다 — (영업이익 + 영업외손익)
  × (1 − 실효세율) × 지배지분비율. 실적은 연결포괄손익계산서 확정값(G1 대사),
  추정 파라미터는 [주관] 태그. 밸류에이션 루트에는 여전히 들어가지 않는다 —
  번역 장치이지 밸류에이션 방법 변경이 아니다. 공시 기본EPS(가중평균·우선주
  구분)와 계산 기준이 다름을 desc에 명시한다.
- 수주·가이던스·채널 체크 같은 비공시 정보. 컨센서스와의 격차가 여기서 올 수 있다
  — 격차를 "시장의 비합리"로 단정하지 않는 이유.
- 목표주가는 대체로 12개월 시계, 본 모델은 최종 추정 연도 시계다. 괴리율을
  나란히 놓을 때 시계 차이를 명시할 것.

**컨센서스는 역산보다 직접값.** 스냅샷 페이지의 펀더멘털 표가 2026E·Fwd12M
EBITDA·EPS·DPS를 직접 준다. 배수에서 역산하지 말 것 (검증용으로는 유용 —
삼성전기 1.8%, 티엘비 1.7% 차이로 역산이 맞았음을 확인했다).

## 6. 면책

투자심사 보고서는 내부 판단 자료다. 라이선스 보유 자문가의 투자권유가 아니며,
모든 수치는 최신 공시로 재확인해야 한다는 문구를 산출물에 포함한다.
