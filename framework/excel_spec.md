# Excel 산출 규격

`ir.json` → `model.xlsx`. Phase 3에서 `tools/build_excel.py`로 구현한다.

---

## 1. 시트 구조

Tesla 예시가 확립한 8시트를 따른다.

| 시트 | 내용 |
|---|---|
| Index | 시트 목차·모델 개요 |
| Control | 시나리오 스위치·전역 설정 |
| Assumptions | 입력 노드 일람 (근거·태그 포함) |
| Model | 계정 트리 × 연도. 수식이 살아있는 본체 |
| Formula Audit | 노드별 수식 원문과 셀 수식 대조 |
| Structure | 트리 구조·깊이·부모자식 |
| Checks | 정합 검증 결과 |
| Metadata | 빌드 시각·소스 해시·YRS·HIST_N |

---

## 2. 컬러 코딩

금융모델링 관행을 따른다. 셀 색이 곧 셀의 성격이다.

| 색 | 뜻 |
|---|---|
| 파랑 | 하드코딩 입력값 (실적·가정) |
| 검정 | 같은 시트 안의 수식 |
| 녹색 | 다른 시트 참조 |
| 회색 배경 | 실적(Historical) 구간 |

---

## 3. 연도 밴드

`HIST_N`으로 실적/추정을 가른다. **모든 시트에서 일관되게.**

Tesla 작업에서 이 부분이 실제로 어긋났다 — 헤더 생성 함수가
"index 0만 실적"으로 하드코딩돼 있어 monkeypatch로 우회해야 했다.
`HIST_N`을 `ir.json`에 실어 보내고, 하드코딩된 상수를 두지 않는다.

---

## 4. 검증 — G7

Excel을 만들고 끝내지 않는다. **만든 파일의 셀 수식을 셀 참조를 따라가며
다시 계산해** HTML 엔진의 산출값과 대사한다 (`tools/xlsx_eval.py`).

- 비교 범위: 전 노드 × 전 연도
- 허용 오차: 0 (표시 자릿수가 아니라 내부 계산값 기준)
- 불일치가 1건이라도 있으면 실패

행 배치가 어긋났거나, `PREV`가 엉뚱한 열을 가리키거나, `IF` 인자 순서가
뒤집혔다면 여기서 값이 갈라진다.

LibreOffice로 재계산하는 편이 더 독립적이지만 현재 컨테이너의 설치가
xlsx를 열지 못한다(최소 파일도 실패). 그래서 직접 평가한다. LibreOffice가
동작하는 환경이라면 그쪽으로 바꾸는 편이 낫다.

삼성전기 모델은 42노드 × 10년 = 420셀 전부 오차 0으로 통과한다.

## 5. 정본은 build_excel.py

Excel 생성 경로가 둘이었다. 브라우저 내 생성(xlsx-js-style + JSZip)과
`build_excel.py`가 같은 8시트를 각자 만들었고 드리프트가 실제로 발생했다.

**`tools/build_excel.py`를 정본으로 정했다.** 브라우저 내 경로는 CDN
라이브러리에 의존해 오프라인에서 죽었고, CI에서 돌릴 수도 없었다.
CDN 스크립트 3종을 걷어내면서 그 경로도 함께 내려놨다 — 버튼은 남아 있고,
누르면 `build_excel.py`를 안내한다.

### 수식 변환은 JS가 정본

`build_excel.py`는 셀 수식을 만들지 않는다. `harness.excel_payload()`가
엔진의 `astToExcel`을 Node에서 돌려 받아온 수식을 **배치만** 한다.

파이썬에 같은 변환기를 두면 변환기가 둘이 되고, 그 둘이 갈라지는 순간
G7 대사는 자기 자신을 검사하는 일이 된다.

### 행 배치 약속

`harness`가 `rowMap`(노드 → 행)과 `dataRow0`를 정하고 수식도 같은 좌표로
만든다. 파이썬은 그 `rowMap`을 그대로 쓴다. 연도는 D열부터 —
`astToExcel`의 `_colLetter(3 + year)`와 같은 약속이다.
