# Excel 산출 규격

`ir.json` → `model.xlsx`. Phase 3에서 `tools/build_excel.py`로 구현한다.

---

## 1. 시트 구조

Tesla 예시가 확립한 8시트를 따른다.

| 시트 | 내용 |
|---|---|
| Index | 시트 목차·모델 개요 |
| Control | 시나리오 스위치·전역 설정 |
| Assumptions | 입력 노드 일람 (근거·태그 포함) |
| Model | 계정 트리 × 연도. 수식이 살아있는 본체 |
| Formula Audit | 노드별 수식 원문과 셀 수식 대조 |
| Structure | 트리 구조·깊이·부모자식 |
| Checks | 정합 검증 결과 |
| Metadata | 빌드 시각·소스 해시·YRS·HIST_N |

---

## 2. 컬러 코딩

금융모델링 관행을 따른다. 셀 색이 곧 셀의 성격이다.

| 색 | 뜻 |
|---|---|
| 파랑 | 하드코딩 입력값 (실적·가정) |
| 검정 | 같은 시트 안의 수식 |
| 녹색 | 다른 시트 참조 |
| 회색 배경 | 실적(Historical) 구간 |

---

## 3. 연도 밴드

`HIST_N`으로 실적/추정을 가른다. **모든 시트에서 일관되게.**

Tesla 작업에서 이 부분이 실제로 어긋났다 — 헤더 생성 함수가
"index 0만 실적"으로 하드코딩돼 있어 monkeypatch로 우회해야 했다.
`HIST_N`을 `ir.json`에 실어 보내고, 하드코딩된 상수를 두지 않는다.

---

## 4. 검증 — G7

Excel을 만들고 끝내지 않는다. **HTML 산출값과 셀 단위로 대사한다.**

- 비교 범위: 전 노드 × 전 연도
- 허용 오차: 0 (표시 자릿수가 아니라 내부 계산값 기준)
- 불일치가 1건이라도 있으면 실패

Tesla는 20노드 × 10년 = 200셀 전부 오차 0으로 통과했다. 그 수준을 기준으로 둔다.

---

## 5. 이중 구현 문제

현재 Excel 생성 경로가 둘이다.

1. 브라우저 내 생성 — `model.html`의 "엑셀" 버튼 (xlsx-js-style + JSZip)
2. `build_excel.py` — `ir.json`에서 생성

둘이 같은 8시트를 각자 만든다. 드리프트가 실제로 발생했다.

**Phase 3에서 정본을 정한다.** 후보:
- `build_excel.py`를 정본으로, 브라우저 버튼은 `ir.json` 다운로드로 축소
- 또는 브라우저를 정본으로, 파이썬은 검증 전용

전자가 낫다 — CI에서 돌릴 수 있고, CDN 의존도 함께 줄어든다.
